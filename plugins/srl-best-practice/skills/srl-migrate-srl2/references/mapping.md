| `assets/…` | `assets/…` = `app/assets/` |

## Gone in SRL 2

`srl init` (→ `npm create @simple-reporting`), `srl prepare`, `srl map`, `beaver`, `mapjs`,
`srl ddev`, `vue3-runtime-template`, the ArticleAutoloader, the PWA plugin, the SRL 1 dev
tools overlay, `ldd` as the name of the editor target (still accepted as an alias).

## Runtime differences that affect project code

- Pages are prerendered (generate) or rendered on the server: no browser APIs during setup.
- URLs: with a menu named `navigation` they follow its hierarchy; otherwise
  `/<locale>/<slug>`, index article `/<locale>`. Hand-built `/<locale>/<slug>` links only
  stay valid without a `navigation` menu; prefer the hrefs of `useSrlMenu()` items.
- Article HTML is parsed once into a render tree; `<srl-*>` tags resolve to components.
  Unknown tags stay plain elements (dev warning `No component registered for <…>`).
- Components are bundled only when used. CSS of unused SRL 1 components disappears from
  the build, which is expected.
